# Phase 17 — Operational Evidence Pack

Phase 17 converts the remaining mainnet requirements into an explicit evidence bundle that can only pass when executed evidence is recorded.

## Added

- `scripts/generate-evidence-pack.mjs` creates an evidence template and SHA-256 manifest.
- `scripts/validate-evidence-bundle.mjs` fails closed unless every required operational evidence item has status `PASS`.
- `npm run evidence:pack` and `npm run evidence:validate` commands.

## Required operational evidence

- Bitcoin reconciliation
- Lightning settlement
- signer recovery
- privacy review
- backup/restore
- staging end-to-end
- production deployment verification

The generated pack is deliberately `NOT_RUN`. Creating the pack does not count as executing a test.

## Current result

The validator correctly returns **NO-GO** because none of the seven operational evidence records has been executed in a real staging/production environment.

This is intentional. A configured CI job, fixture, or checklist is not evidence that the underlying operation succeeded.

## Release principle

Evidence must be generated by an actual run and retained with its operator, environment, timestamp, and artifact reference. This supports the outcome-oriented approach of NIST SP 800-218 (SSDF 1.1).
